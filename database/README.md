# TrafficFlow Database

PostgreSQL schema for TrafficFlow, written as plain SQL. For the current milestone (the login stage), it contains only the `users` table.

```
database/
├── migrations/     # Numbered SQL files, applied in order by `npm run db:migrate`
│   ├── 001_create_types_and_functions.sql
│   └── 002_create_users.sql
└── docker-init/    # Runs once when the Docker Compose PostgreSQL is first created
    └── 01-create-test-database.sql   # The empty trafficflow_test database for the tests
```

The migration script lives in the backend (`backend/src/scripts/migrate.ts`). Run it from the `backend` folder.

## Starting PostgreSQL

In the repository root, with Docker Desktop:

```powershell
Copy-Item .env.example .env      # first time only: then set POSTGRES_PASSWORD in .env
docker compose up -d db
docker compose ps                # "db" should show (healthy)
```

Then, in `backend/`, put the same password in `DATABASE_URL` in `backend/.env`, and run `npm run db:migrate`. Installing PostgreSQL on Windows instead of using Docker is covered in [backend/README.md](../backend/README.md#getting-started).

## The users table

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | Primary key, generated by `gen_random_uuid()` |
| `full_name` | `VARCHAR(100)` | Required, can't be blank |
| `email` | `VARCHAR(255)` | Required, unique ignoring case (`users_email_lower_key` index on `LOWER(email)`) |
| `phone` | `VARCHAR(20)` | Optional |
| `password_hash` | `TEXT` | bcrypt hash. The plain password is never stored. |
| `role` | `user_role` | `CITIZEN`, `OPERATOR`, `RESPONDER` or `ADMIN`. The default is `CITIZEN`, and public registration always uses it. |
| `is_active` | `BOOLEAN` | Default `true`. Deactivated accounts can't log in. |
| `last_login_at` | `TIMESTAMPTZ` | Set at each successful login |
| `created_at` | `TIMESTAMPTZ` | Default `now()` |
| `updated_at` | `TIMESTAMPTZ` | A trigger (`set_updated_at()`) updates it on every change |

## How migrations work

- `npm run db:migrate` applies every file that hasn't run yet, in name order. Running it again does nothing.
- Each file runs in a transaction and is recorded in the `schema_migrations` table with a SHA-256 checksum.
- If a migration that already ran is edited later, the script refuses to run. Schema changes go in a new file, e.g. `003_add_something.sql`.
- `npm run db:status` lists applied and pending migrations.
- `GET /api/health/ready` reports `ready` only when every migration has been applied.

## Useful commands

From the repository root (Docker setup):

```powershell
# Open a SQL prompt. Try: \dt (tables), \d users (the users table), SELECT email, role FROM users; and \q (quit)
docker compose exec db psql -U trafficflow trafficflow

# Remove PostgreSQL and ALL its data. "docker compose up -d db" then starts from scratch.
docker compose down -v
```
